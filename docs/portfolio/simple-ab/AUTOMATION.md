# A/B 운영 품질 자동점검

방문 통계나 실험 관리는 하지 않는다. 자동화 대상은 기술적 품질과 원본 보존,
승인된 포트폴리오 개선, 공개 코드 없는 프로젝트의 독립 데모 구현이다.
외부 분석 서비스·새 호스팅·계정 연결은 추가하지 않는다.

## 운영 정책

- 프로젝트 개발: 매일 오전 9시, Asia/Seoul. 부족한 부분의 조사·우선순위·대상 선정·로컬 구현·검증은
  에이전트에게 위임한다. 하루 의미 있는 로컬 개발 산출물은 최대 한 건이며, 매번 소유자 선택을 기다리지 않는다.
- 페이지 디자인/전체 품질 점검: 월요일 오전 10시. 승인된 본문 디자인 개선은 주간 최대 한 건이다.
- 프로젝트 업데이트 연결: 매시간 20분에 가볍게 변경을 감지한다. 공개 프로젝트의 push 메타데이터와
  검증 산출물 상태가 바뀔 때만 에이전트를 호출하고, 실제 관련 변경을 확인해 검토용 반영 초안을 만든다.
- Mac과 기존 Hermes gateway가 실행 중일 때 로컬에서 수행한다.
- 격리된 임시 복사본에서 빌드·A/B 배정/저장·no-JS·링크·이미지/PDF·모바일·접근성을 검사한다.
- 작업 중인 체크아웃이 dirty이거나 점검 도중 바뀌면 대기/보고한다. 사용자 파일을 되돌리지 않는다.
- 주간 페이지 작업은 전체 기술검사 후 승인된 디자인 작업을 확인한다. 독립 프로젝트 개발은
  이 주간 주기를 기다리지 않고 개발 일일 작업에서 수행하고 해당 데모를 직접 검증한다.
- 시간별 변경 감지는 무변화 시 모델을 호출하지 않는다. 최초 수집은 기준선이지 새 업데이트의
  증거가 아니다. push 시각만 보고 공개 설명/성과를 바꾸지 않고 공개 기본 브랜치의 관련 변경을 검증한다.
- 재현되는 코드 결함은 최소 수정안을 검증하고 초안 PR로 제안한다. 이미 검토 중인
  동일 문제의 PR은 중복 생성하지 않는다. 세부 로그·스크린샷·대기 작업은 로컬 비공개다.
- 기존 두 히어로와 사실을 유지한 시각 개선은 전후 화면과 근거를 함께 검토받는다.
- Claude Code는 제한된 별도 작업공간에서 구현하고, Hermes가 실제 테스트·UI를 검증한다.
  공개 링크가 없다는 이유로 비공개 원본을 공개하거나 복사하지 않는다. 새 구현은 원본
  회사 코드와 다른 독립 데모로 표시하며, 새 공개 저장소 생성은 소유자 승인 후에 한다.
- 개발/디자인 작업은 서로의 대기열을 대신 처리하지 않는다. 실제 진행 중 작업은 중복 생성하지 않는다.
  개발 대기열이 비면 공개 포트폴리오와 공개 코드를 조사해 다음 기술 보완 과제를 선정한다.
  실제 프로젝트의 핵심 기술·기능을 맞춰 구현하며, 무관한 간단한 예제로 완료 처리하지 않는다.
- 로컬 구현·검증 완료와 외부 공개 승인은 별도 상태다. 다른 산출물의 공개/디자인 검토 대기가
  새 로컬 개발 전체를 막지 않는다. 공개·비공개 자료 노출·새 유료 비용·해결 불가능한 비공개 요건만 확인받는다.
- 업데이트 반영은 주간 디자인 작업을 기다리지 않되, 기존 초안과 진행 중 작업을 확인해 중복/경합을
  피한다. 로컬·비공개·검토 대기 데모를 공개 코드로 연결하지 않는다. 모든 공개는 별도 승인 사항이다.
- 네트워크·인증·도구·계정 배포 차단은 보고만 한다. 결제/권한/호스팅 우회 변경은 하지 않는다.
- 병합·배포·기본 홈 교체·방문자 비중 조정은 자동화하지 않는다.

## 실행과 증거

실행기는 `tools/portfolio_maintenance.py`, 단위 검증은
`tools/test_portfolio_maintenance.py`다. 예약 작업은 이 실행기의 검증된 사본과
설정·QA 자산을 사용자 프로필의 비공개 자동화 디렉터리에 설치해 사용한다.
주간 실행에 필요한 axe 파일은 24시간 scratch 캐시 밖에 보관하고 원래 라이선스
고지와 파일 hash를 보존한다. QA의 결과 경로는 환경 변수로 격리한다.

일정 등록, 스케줄러의 실제 가동, 최초 실행의 성공, 결과 전달은 별도로 확인한다.
예약 등록만으로 작동 완료라고 보지 않는다. TUI 전달은 대화 기록의 알림이며
휴대폰 푸시를 뜻하지 않는다. 실제 설치/실행 영수증은 비공개 프로필에 보관한다.

현재 A/B 소스는 초안 PR #3의 기능 브랜치다. PR이 병합/종료되거나 대상 체크아웃이
제거되면 대상을 갱신하기 전까지 자동 수정하지 않는다. 원본 공개 홈의 HTTP 성공은
새 `/ab/` 경로의 배포 증거가 아니다. 공개 배포 차단은 이 자동점검과 별도로 남는다.
