# C 방향 — 템플릿을 더 꾸미지 않기

## 사용자 피드백

B가 샤프하지만 미묘하게 맞지 않고, 정형적이며 AI가 만든 것처럼 느껴진다는
피드백을 받았다. 이것은 사용자의 미적 판단이며 AI 탐지 결과가 아니다.
원문은 공개 저장소 밖의 로컬 비공개 피드백 기록에 보존했다. A와 B는 수정·삭제하지 않는다.

## 더 본 레퍼런스와 적용할 것

- Paco Coursey의 공개 소개와 프로젝트/글/현재 관심사 구성은 거대한 경력 광고보다
  한 사람의 구체적인 활동을 읽게 한다.[1] 본문은 읽었지만 이번 자동화 브라우저의
  시각 렌더는 안정적으로 확인되지 않아, 빈 캡처를 사이트 결함으로 판단하지 않았다.
- Maggie Appleton의 홈페이지는 본인이 하는 일을 직접 설명하고, 시각 에세이·노트·
  패턴 등 서로 다른 내용이 구분된다.[2] 부모 에이전트가 실제 화면도 확인했다.
- Max Böck의 사이트는 간단한 자기소개와 개별 글의 다른 이미지가 전면에 나온다.[3]
  부모 에이전트가 실제 화면도 확인했다. 타인의 취향이나 개인사를 옮겨오지 않는다.
- Henry Desroches의 원문은 편지, 개인 소개, 작업, 글을 한 사람의 문맥으로 엮는다.[4]
  이를 근거로 강남의 정치관·취향·음악·인생 이야기를 만들어내지는 않는다.

이 연구는 유행의 통계나 어떤 디자인의 우월성을 증명하지 않는다.
참고할 것은 내용에서 생기는 차이와 목소리이며, 색·폰트 조합의 복사가 아니다.

## 이번 가설

B의 거대한 슬로건, 반복되는 번호/등폭 라벨, 동일한 프로젝트 필드, 숫자 패널은
이번 사용자의 목적에 비해 템플릿의 존재감을 키웠다. C는 이름과 간단한 설명 뒤에
실제 작업을 먼저 보여주고, 프로젝트마다 그 자료에 맞는 다른 비중과 구성을 쓴다.

- 추상 도식 대신 기존 공개 데모와 실제 개발 화면을 사용한다.
- 모든 프로젝트를 같은 카드, 같은 질문, 같은 수치 개수로 채우지 않는다.
- 자연스러운 문장과 구체적인 작업명을 쓴다. 없는 블로그 글·후기·취미·일화는 쓰지 않는다.
- 손글씨 흉내, 무작위 회전·정렬 깨짐으로 사람다운 인상을 제조하지 않는다.
- 프로토타입, 운영 모듈, 개인 프로젝트의 범위는 유지하되 불필요한 방어문구를 반복하지 않는다.
- 한국어 시안의 방향을 먼저 비교한다. A/B의 기존 다국어 페이지는 그대로 남긴다.

## 실제 자료의 범위

`asset-provenance.json`은 원본과 파생본 SHA-256, 실제 GIF 프레임, 크롭과 크기를 기록한다.
UE5는 실제 마지막 프레임의 오브젝트가 보이는 장면이며, 생성한 가짜 렌더가 아니다.
개발 손 추적 화면의 FPS·가시성 값은 디버깅 표시이지 검증된 서비스 성능이 아니다.
기존 지침에서 학생 얼굴로 표시한 head 이미지는 재사용하지 않는다.
달결과 Story Writer의 화면은 예시 UI이며, 출시·실사용자·모델 품질을 보증하지 않는다.

## 비교/운영 경계

C는 별도 `/c/` 시안이다. 기본 홈을 바꾸지 않으며 공개 배포, 통계 수집, 트래픽 분산,
자동 승격은 하지 않는다. 이전 137개 추적 파일과 62개 렌더 경로를 기준선으로 보존한다.
코드·접근성 검증 통과는 미적 피드백의 대체가 아니다. C가 더 맞는지는 사용자가 보고
평가해야 하며, 이번에도 다르면 그 차이를 구체화해 다음 실험에 반영한다.
